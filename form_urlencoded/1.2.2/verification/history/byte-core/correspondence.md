# Release correspondence and observed runtime changes

The release snapshot is `capture/source`; the independent fork is `crate`. The source version is crates.io `form_urlencoded` 1.2.2 with archive SHA-256 `cb4cb245038516f5f85277875cdaa4f7d2c9a0fa0468de06ed190163b1581fcf`. `.cargo_vcs_info.json` names rust-url commit `91377f48bf35011d042aa5abef9e7f2a0a625aaa`, path `form_urlencoded`, and marks the tree dirty. This establishes archive identity and recorded commit metadata, not Git-tree equality.

The `Parse::next` body now calls `raw_pair_bounds`, then slices the same nonempty segment at its first equals byte. It preserves the previous behavior of skipping repeated/leading/trailing ampersands, treating the first equals as the split, and assigning an empty value when equals is absent. The absent-equals branch retains the release's empty `&[]` slice choice. The custom `Iterator` implementations for `Parse`, `ParseIntoOwned`, and `ByteSerialize` are compiled only when `cfg(creusot)` is absent because Creusot 0.13 requires `IteratorSpec` refinements that are outside this milestone. Native builds use the refactored `Parse::next` and original iterator implementations.

`replace_plus` now calls checked `find_plus` and `replace_plus_in_place` helpers. It still returns a borrowed `Cow` when no plus exists, allocates an owned byte vector when plus exists, maps every plus to a space, and preserves all other bytes and length. The fork uses slice `to_vec` in place of `to_owned`; native differential evidence compares public values and Cow variants.

`byte_serialized_unchanged` has a checked exact membership contract. New `percent_encoded_bytes` is a locally implemented exhaustive 256-arm match that returns static numeric byte triples. Its contract specifies `%`, exact uppercase high/low hexadecimal digits, and ASCII for each byte. The existing `ByteSerialize::next` runtime path now converts this helper's checked ASCII bytes with `str::from_utf8_unchecked`; no percent-encoding algorithm is delegated to an external crate. The iterator wrapper and standard-library string conversion are excluded from formal proof. The Why3 configuration grants five seconds per prover attempt so Z3 can discharge the generated match-exhaustiveness obligation; all byte-output obligations remain unchanged.

The differential harness compares actual public APIs from the fork against an extracted capture-source copy. The copy's `src/lib.rs` SHA-256 matches the immutable capture source (`766b5d679064e01f7e6cce6f127a23885f79806ce3bccc49e4fe41933b83fd8d`). Its Cargo package name alone was changed from `form_urlencoded` to `form_urlencoded_upstream` to allow both 1.2.2 path packages in one Cargo lockfile; its library name and Rust sources are unchanged.

The differential runner checks 85,529 finite byte inputs: all 256 singleton bytes, all 65,536 two-byte combinations, every byte string of length 0 through 5 over `&=+%0F\x80` (19,608 strings), and 129 deterministic xorshift byte arrays at lengths 0 through 128. Each input compares byte-serializer chunk boundaries and strings, plus parsed pair values and borrowed/owned Cow variants. The harness also compares one `Serializer::for_suffix` sequence with a pair and key-only append. The runner verifies the upstream-copy Rust source hashes against the immutable captured source on every run, emits JSON input counts, and stores logs in a fresh directory. This is finite native correspondence evidence and does not establish equivalence for all byte strings or prove excluded APIs.

The serializer iterator body itself is excluded from Creusot proof compilation with its Iterator impl. The checked byte helper governs the runtime encoder path, but correspondence from byte triples through `from_utf8_unchecked` and iterator chunk progression is not formally claimed. `decode`, percent decoding, lossy UTF-8 conversion, encoding callbacks, and `Serializer` methods are also excluded from formal claims.
