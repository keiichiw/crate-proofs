# ipnet 2.12.2 — managed Aeneas profile

```bash
bash scripts/setup.sh
bash scripts/verify.sh
bash scripts/verify.sh --offline
```

The release archive and complete source inventory are fixed in `source.lock.json`.
The standalone Cargo workspace compiles unchanged Git-tracked `upstream/` bytes and preserves
release features/dependencies. Default, no-default and all-feature native tests run
separately from the formal checks.

See the [management guide](../../verification/aeneas-management.md) and the
[default profile](aeneas/profiles/default) for the independent specification, theorem
inventory, API mappings, generated target models and exact tool locks. Both Aeneas
and Charon have fixed, separately described patches; their resulting trees are checked.
The original LLBC runtime-check settings, standard Rust source hashes and checked
shift overflow examples are mandatory. The extraction and standard-library models
remain trusted translation boundaries. Runtime-model claims do not cover general
const evaluation or panic formatting/abort equivalence.

[Results](aeneas/profiles/default/results.md) distinguish accepted runs from Linux
candidates and historical evidence. Only named audited contracts establish coverage.
Only explicitly inventoried compatibility fixtures remain under evidence/legacy; complete original records are in the local archive identified by evidence/archive.json.
Local verify requires no push. The optional record wrapper uses standard Lake/CLI
audits and retains committed/pushed-source requirements; repository scripts and
preparation/native logs are excluded from SARIF. Setup/verify never publish.



Verification findings are recorded [within this version](verification/findings/README.md).

## Record the maintained Lean proofs

Rust release files are tracked under `upstream/` and checked against
`source.lock.json`. Lean models and proofs build directly in the tracked default
profile, on macOS arm64. The recording path does not run setup or extraction.

```bash
CARGO_PROOFS_BIN=/absolute/path/to/cargo-proofs bash scripts/record.sh
```

Use the locally built CLI with `charon_patch` support. `prepare` restores official
Aeneas and Charon sources with the independently pinned patches; it does not build
or execute the extractors. Recording checks the maintained Lean proofs and marks
Charon and the Aeneas translator as `not_run`. It does not establish that the saved
models were generated by those tools. The setup/verify wrappers remain the separate
extraction and native verification workflow. Historical results retain their original
input identities; they are not acceptance evidence for this new layout.

See [standard CLI migration validation](aeneas/profiles/default/standard-cli-migration.md) for the new layout checks and recording boundary.

### CLI revision for recording

Use [proofs-rs PR #82](https://github.com/proofs-rs/proofs-rs/pull/82), commit
`8c98569c8be379007d0649816d35de260ca43822` from
`https://github.com/keiichiw/proofs-rs.git` (branch
`codex/aeneas-charon-api-mappings`). In a checkout of that commit, build with
`cargo build --locked --manifest-path cli/Cargo.toml`, then pass the absolute
`cli/target/debug/cargo-proofs` path as `CARGO_PROOFS_BIN`.
The globally installed CLI may not contain these features.
