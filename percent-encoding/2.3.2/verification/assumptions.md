# Assumptions and external models

This ledger describes the model boundaries for the expanded feasible API scope. It is not a proof result; use [results.md](results.md) for current integrated status and evidence. Model validity, application-code proofs, native differential evidence, and upstream equivalence are separate claims. The exact identity and limits of the pinned `form_urlencoded 1.2.2` proof dependency are recorded in [dependency-ledger.md](dependency-ledger.md).

No application algorithm is marked trusted. Iterator transitions, mask operations, equality, clone state, Cow assembly, formatter-request recording, and UTF-8 relations are checked application code or checked logical definitions. External models below are limited to library boundaries.

## Iterator and state-model composition

`PercentEncode` equality is equality of the exact remaining raw bytes and configured four-word set mask. `PercentDecode` clone preserves its current remaining iterator suffix. `PercentEncode` clone preserves both its current suffix and configured set. Consequently, clone/equality describe the current state after partial consumption, not merely the original constructor input or the eventual encoded output.

The crate supplies contracts for its own `Iterator::next`, `size_hint`, and `IteratorSpec` implementations. The `IteratorSpec` production relations connect emitted chunks/bytes and the remaining state to checked encoder/decoder trace models; the trait laws implemented in this crate are separate positive targets. Standard-library default methods such as `count`, `fold`, `nth`, or `collect` are not individually proved by proving `next`; inherited `PartialEq::ne` and `Clone::clone_from` are likewise not separately verified, and no blanket refinement is claimed for arbitrary consumers. Size-hint body contracts likewise do not establish a generic standard-library law beyond the explicit bounds in their postconditions.

## Partial domains and panic behavior

`AsciiSet::contains` has the precondition `byte < 128`. `AsciiSet::add` and `remove` specify exact changes only under `byte < 128`; outside that domain their array indexing can panic, and no postcondition is claimed. `should_percent_encode` is defined for every byte: all bytes at least 128 are selected, while ASCII bytes are tested against the mask. The proofs do not assume an array index is safe outside these stated domains.

The standard library's UTF-8 observer adequacy is intentionally limited to the exposed contract: strict success/failure validity, returned text contents on success, and the two public `Utf8Error` observations above. Lossy conversion is related to the standard library's own model rather than re-proving that implementation. These boundaries must remain visible when reporting strict or lossy UTF-8 results.

## Solver policy

The direct proof runner records the exact generated SMT input, tool version, command line, timeout, and result. Z3 is the primary solver. CVC5 may be recorded as a secondary solver only when it checks the same unmodified exported SMT file; its result is reported separately and does not replace or erase a primary Z3 timeout. No assumptions, axioms, or goal transformations may be removed to obtain a secondary result. Solver outcomes establish the generated verification conditions under the recorded backend and budget; they do not validate the adequacy of external standard-library contracts listed above.
