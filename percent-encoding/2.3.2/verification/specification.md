# Verification specification

The target list and generated-target classification are maintained in `target-inventory.json`. Exact run results and evidence fingerprints are maintained separately in `results.md` and the evidence bundle.

`percent_encode_byte(b)` produces the three ASCII bytes `%`, uppercase hex for `b / 16`, and uppercase hex for `b % 16`, unconditionally. The space byte therefore produces `%20`. `percent_encode` and `utf8_percent_encode` preserve their input bytes and configured `AsciiSet` state.

`AsciiSet` stores four private `u32` words. Its checked logical view has length four and exposes exact mask semantics without changing field visibility. `EMPTY` is `[0, 0, 0, 0]`; `CONTROLS` is `[0xffffffff, 0, 0, 0x80000000]`; `NON_ALPHANUMERIC` is `[0xffffffff, 0xfc00ffff, 0xf8000001, 0xf8000001]`. For byte values below 128, membership selects the corresponding bit. `should_percent_encode` is true for every non-ASCII byte or a member of the set. `add` and `remove` specify only the safe `byte < 128` domain. Union and complement are wordwise bit operations; `Add` and `Not` refine those operations. Equality compares mask state. Debug proof covers the requested struct/field trace, typed mask value, and formatter result, not the rendered text.

The encoder's chunk model partitions input into maximal safe ASCII runs and one `%HH` chunk per selected/non-ASCII byte. The `PercentEncode` iterator yields exactly those chunks in order, preserves its set, consumes input on `Some`, and leaves the complete state unchanged on `None`. Its size hint has lower bound zero for empty input and one otherwise, with the remaining input length as upper bound. State equality compares remaining raw bytes and configured mask; cloning preserves both. `Into<Cow<str>>` has exact encoded UTF-8 bytes, with borrowed output for zero or one chunk and owned output for two or more chunks.

The decoder accepts only ASCII hexadecimal digits. A valid `%HH` consumes three input bytes and returns the combined byte; all malformed or truncated percent escapes preserve the percent byte literally and consume one byte. The recursively defined `decoded_trace` has an explicit empty-input base and defines the full decoded byte sequence. The public iterator produces that trace, obeys its checked iterator laws, and has lower bound `ceil(remaining_bytes / 3)` and upper bound `remaining_bytes`. `PercentDecode` to `Cow<[u8]>` preserves input borrowing when no escape is decoded and otherwise yields exactly decoded bytes.

Strict UTF-8 conversion returns a borrowed value only when the decoded bytes are unchanged and valid; otherwise a valid owned conversion contains exactly those decoded bytes. On error, the returned standard `Utf8Error` fields match the checked local recognizer's error offset and length. The recognizer and the standard validator are connected only through the declared standard-library boundary. Lossy conversion satisfies the checked scalar replacement relation. For unchanged bytes it also preserves the inherited `String::from_utf8_lossy` contract, including its borrow policy; changed decoded input returns owned output. No unproved equivalence between independent UTF-8 parsers is assumed.

Display proof records the ordered string chunks requested from `Formatter::write_str` and the status of each call; it returns the first error unchanged. It does not promise rendered bytes from arbitrary formatter sinks. Debug proof records struct name, ordered field names, typed snapshots, and final call status for `AsciiSet`, `PercentEncode`, and `PercentDecode`; it does not claim the final textual rendering.

The proof uses checked public form models for uppercase hex, ASCII triples, byte-sequence conversion, and standard UTF-8 boundaries. It does not infer a whole decoder theorem from the dependency's opaque indexed decoder model. Local checked sequence and UTF-8 lemmas establish only the contracts stated in the generated target inventory and assumptions ledger.
