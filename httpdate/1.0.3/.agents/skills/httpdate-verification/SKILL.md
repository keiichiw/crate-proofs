# httpdate 1.0.3 verification

1. From the repository root, run `source scripts/activate.sh`. The workspace is specific to `httpdate/1.0.3/`. Before work, read the version's `AGENTS.md`, this skill, `verification/upstream.md`, `verification/specification.md`, `verification/coverage.md`, and, when relevant, `verification/trial/method.md`.
2. `RawDate` is a permissive parser / arithmetic record; public `HttpDate` is a flat seven-field record with a checked `valid_calendar` invariant. Do not treat a raw value returned by a parser as a public value. Check the contracts for `as_raw` / `from_raw` and every constructor path.
3. Follow the specification and coverage for selected public-wrapper contracts. The selected surface includes `FromStr` / `parse_http_date`, bounded `fmt_http_date` and `Display`, `Eq` / `Ord` / `PartialOrd` / `Clone`, and time conversions. `Eq` compares seven fields; `Ord` compares integer seconds. Do not confuse bounded body reasoning for `From<SystemTime>` with a proof of an unconditional trait refinement. There are native panic counterexamples before the Epoch and from year 10000 onward, so the forward refinement remains open. Normal and pretty Debug output is selected only under plain options and a faithful append-sink condition.
4. List the standard-library specifications used by production wrappers in `verification/stdlib-assumptions.md`. Report the conditions on the declarations in the ledger, the 64-bit Linux or macOS arm64 / supported date domain, and the Formatter `Ok && append_sink` condition with proof results. Do not claim to prove the standard-library implementation. Do not mark date logic or application wrappers as trusted.
5. Preserve the `IMF → RFC850 → asctime` priority in `parse_date_bytes`. Success from the raw parser does not imply calendar validity. When changing public-parser error completeness, check the contracts for all three grammars. If a caller uses an opaque child-grammar predicate, preserve the bounds and uniqueness bridge in checked `encoding_laws`. Byte 9 between the RFC850 year and time remains unchecked, matching upstream.
6. Investigate Creusot 0.13 translation with small diagnostics. In environments where `@` on Ghost string literals causes an ICE and runtime byte-string literals reach the backend `Bytes` todo, use scalar byte constants / comparisons in common runtime code and numeric byte predicates on the ghost side. If indexing an entire array with `[..]` (`RangeFull`) lacks a contract, state the reference / extensionality contract for every whole-array use that needs it.
7. Include helper laws, trait refinements, and all generated implementation / closure goals in coverage. Zero goals generated for a Clone without a postcondition do not show an exact copy. Add a meaningful refinement such as `result == *self`, then inspect the target VC and complete proof tree.
8. Report native tests and upstream differential tests separately from formal proof. Tests should construct only valid public `HttpDate` values; do not call finite samples formal upstream equivalence. Use only a manifest matching the latest source fingerprint. Refer to the manifest for target totals instead of hard-coding them. `bash httpdate/1.0.3/scripts/verify.sh` is the standard command for native checks and a fresh full proof run. A partial run or old manifest does not establish overall success.
9. Registration in public API `proofs.rs` / SARIF is a separate task and is not included in current private/source proof evidence. Do not log in, push, publish, or deploy without explicit authorization.
10. Before writing a report about the distributed crate, read `verification/correspondence/README.md` and `release.json`. Matching package versions alone does not establish correspondence with a distribution. `scripts/check-upstream-release.py` normally checks only the local hash. To check the distributed archive itself, use `--archive` or explicit `--fetch`, and distinguish the captured registry checksum, release VCS commit, source-copy commit, and actual source. `bash httpdate/1.0.3/scripts/check-correspondence.sh` runs a standalone locked native comparison without formal tools or a formal manifest; it may fetch Cargo dependencies and saves `native-manifest.json`. Only the separate `capture-correspondence.py --bind RUN_DIRECTORY` step checks formal-manifest and source/tool hashes and promotes formal-bound evidence. Preserve this separation when changing the workflow. Matching representative times on every civil day is not formal equivalence across all seconds and inputs.
11. Submission drafts have been removed; create new ones only when requested. The inspected cargo-proofs 0.3.4 Creusot importer records only `panic_contract`. Do not describe it as registering functional postconditions or `no_ub`. Since the current proof runner uses `--span-mode off`, do not assume it can be used directly for API recording; check source spans and catalogue mapping for any future recording. Do not hide the open `from__refines` result behind a successful bounded `from` body proof, and describe callback non-panicking behavior as a boundary assumption. Even `publish --dry-run` may connect to or operate on a server, so do not run it for a request to prepare an unsubmitted report.

`Hash` is a checked implementation that preserves the types and order of the original seven fields. For supported deterministic, non-panicking hashers, it guarantees equal results for equal `HttpDate` values hashed from the same initial internal state. `DefaultHasher::new` is connected as a concrete fixed-key example. No guarantee is made for arbitrary hashers, collision freedom, digest equality across different seeds or Rust versions, or the operation sequence of `hash_slice`. See the specification, assumptions ledger, and latest manifest for details.

The checked implementation of `Error`'s stable trait methods returns `None` from `source` / `cause` and the standard deprecated message from `description`. `From<Error> for io::Error` preserves the `Other` kind and original concrete payload. Under the conditional std model, the body, refinement, and kind-observer harness are proved. Formal guarantees do not cover arbitrary `Into` converters, dynamic `get_ref` / downcast / `into_inner` observers, unstable `provide`, or hidden `type_id`.

The checked Debug implementation explicitly formats the original seven field names and order of public `HttpDate`, and the unit tuple for `Error`. It guarantees exact normal and pretty output for plain flags 0 / 4, with no width / precision / alignment and a space fill, when the result is `Ok` and the sink is an append sink. Pretty-mode numbers are written once by a checked decimal helper, matching the standard `PadAdapter` behavior that omits empty strings. Other format options are passed to the standard builder to preserve native behavior, but their content is not formally guaranteed. Native comparison includes nested formatting and the call sequence of failing writers. See the specification, assumptions ledger, and latest manifest.
