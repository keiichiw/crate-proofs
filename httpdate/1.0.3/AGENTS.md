# httpdate 1.0.3 work policy

- Follow the root `.agents/skills/creusot-verification/SKILL.md` for common procedures and `.agents/skills/httpdate-verification/SKILL.md` for this version's scope. Before work, read `verification/upstream.md`, `verification/specification.md`, and `verification/coverage.md`.
- Follow the latest manifest whose source matches `verification/coverage.md` for current scope and status. `verification/trial/method.md` describes the feasibility trial's method, boundaries, and related evidence. If source, proof targets, tests, or scope change, do not use old evidence as proof of success.
- Run commands in the version-specific workspace. From the repository root: `source scripts/activate.sh && bash httpdate/1.0.3/scripts/verify.sh`. Check all generated implementation/helper-law Coma and target VCs. Report native tests separately from formal proof. Do not fix goal counts; refer to coverage and the manifest.
- The type boundary is between private permissive `RawDate` and public `HttpDate` with a checked `valid_calendar` invariant. `as_raw` / `from_raw` are checked bridges that preserve all seven fields. Success from the raw parser alone does not imply calendar validity. The parser kernel's failure contract covers all IMF, RFC850, and asctime encodings; the legacy children’s checked `encoding_laws` connect grammar lengths and uniqueness. Byte 9 between the year and time in RFC850 is unconstrained, matching upstream behavior.
- Refer to the specification, coverage, and latest manifest for the selected production proof surface. It includes public `FromStr` / `parse_http_date`, bounded `fmt_http_date` / IMF `Display`, public `HttpDate` `Eq` / `Ord` / `PartialOrd` / `Clone`, and some time conversions. `Eq` compares the same seven fields; `Ord` compares integer seconds. One forward `From<SystemTime>` refinement is open as an unconditional contract because native code panics before the Epoch and in year 10000. Do not treat an in-range body proof as closing this gap. Normal and pretty Debug output is verified under the ledger's plain options and faithful append-sink conditions. Public API `proofs.rs` / SARIF registration has not been done.
- Production wrapper proofs depend on the conditional standard-library declarations listed in the ledger. Report the 64-bit Linux or macOS arm64 platform, supported date domain, and Formatter sink conditions as described in [the assumptions ledger](verification/stdlib-assumptions.md). Formatter content is guaranteed only when `Ok(()) && append_sink`; there is no guarantee for arbitrary sinks, partial writes on `Err`, or initial output. Do not call this a proof of the standard-library implementation.
- Native differential tests are regression evidence for the inputs compared, not a formal equivalence proof with upstream. Do not state aggregate counts that are absent from coverage and the latest manifest. Treat unselected APIs and explicitly open / unverified properties as unverified.
- Use Luna's process for routine investigation and fixes. Consult Astra for proof stalls and difficult models or specifications; ask primary for the final review of contracts, evidence, and scope.
- Do not log in, push, publish, or deploy without explicit authorization.

`Hash` is a checked implementation that preserves the types and order of the original seven fields. For supported deterministic, non-panicking hashers, it guarantees equal results when equal `HttpDate` values are hashed from the same initial internal state. `DefaultHasher::new` is connected as a concrete fixed-key example. No guarantee is made for arbitrary hashers, collision freedom, digest equality across different seeds or Rust versions, or the operation sequence of `hash_slice`. See the specification, assumptions ledger, and latest manifest for details.

The checked implementation of `Error`'s stable trait methods returns `None` from `source` / `cause` and the standard deprecated message from `description`. `From<Error> for io::Error` preserves the `Other` kind and original concrete payload. Under the conditional std model, the body, refinement, and kind-observer harness are proved. Formal guarantees do not cover arbitrary `Into` converters, dynamic `get_ref` / downcast / `into_inner` observers, unstable `provide`, or hidden `type_id`.

The checked Debug implementation explicitly formats the original seven field names and order of public `HttpDate`, and the unit tuple for `Error`. It guarantees exact normal and pretty output for plain flags 0 / 4, with no width / precision / alignment and a space fill, when the result is `Ok` and the sink is an append sink. Pretty-mode numbers are written once by a checked decimal helper, matching the standard `PadAdapter` behavior that omits empty strings. Other format options are passed to the standard builder to preserve native behavior, but their content is not formally guaranteed. Native comparison includes nested formatting and the call sequence of failing writers. See the specification, assumptions ledger, and latest manifest.
