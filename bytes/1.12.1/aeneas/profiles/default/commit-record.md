## Finding and unresolved scope

A confirmed safe signed-read discrepancy remains in the unchanged release:
`[0xff, 0x42]` followed by width-one `get_int` yields -1, while `try_get_int`
yields Ok(255); both leave `[0x42]`. BE, LE and native variants reproduce it.
`findings/signed-read/` includes an executable reproducer, saved observations
and independent review. The intended signed contract remains a failed obligation.

The generic unchecked default copy wrapper still reaches unsupported
Drop/Destruct lookup when standard unwrap_or_else is selected transparently.
Actual variable-width reader extraction still reaches size_of/default-copy
model gaps or a projected-declaration cycle. `blockers/stage3-dispatch/` preserves
precise later probes without replacing older failures. No partial/axiom model
was accepted. Arithmetic helpers are not actual reader API verification.

Range proofs assume successful bound queries and operate in the extracted model;
they do not cover arbitrary user-defined destructor or unwinding effects.
Unsafe fast paths, operational BufMut storage, Bytes/BytesMut ownership,
allocation, pointer provenance, reference counts, Drop and concurrency remain
outside the verified scope. See `specification.md`, `safe-scope-ledger.md`,
`oracle-stage3-review.md` and `results.md` for detailed contracts and boundaries.
